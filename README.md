# OSCAR Gaming images

เว็บ**ทำป้ายขายไอดีเกม** — ลูกค้าเลือกสกินที่มี ระบบเรียงตามความหายาก แล้วได้ภาพเดียวพร้อมโพสต์ขาย จัดและดูตัวอย่างฟรี **จ่ายเป็นคอยน์เมื่อดาวน์โหลด** (ค่าเริ่มต้น 0.3 คอยน์/สกิน, ไม่มีลายน้ำ +5 คอยน์) หรือ**รายเดือน 199 คอยน์ ดาวน์โหลดไม่จำกัด** เติมคอยน์ด้วยพร้อมเพย์ + อัปโหลดสลิป (ตรวจอัตโนมัติด้วย SlipOK หรือแอดมินอนุมัติเอง) สร้างด้วย Next.js (App Router) — มีเฉพาะส่วนทำป้าย (ส่วนร้านขายไอดีถูกนำออกแล้ว)

## ฟีเจอร์หลัก

**ฝั่งลูกค้า** (ไม่ต้องล็อกอิน)
- **เพิ่มรูปสกินที่ยังไม่มีรูปเอง:** กดไอคอนกล้องที่มุมช่อง → ครอป → ใช้ในป้ายของตัวเอง รูปเก็บใน IndexedDB ของเบราว์เซอร์ลูกค้าเท่านั้น **ไม่ถูกอัปโหลดขึ้นเซิร์ฟเวอร์** (เว็บไม่เก็บรูปลิขสิทธิ์ของลูกค้า) ล้างข้อมูลเว็บไซต์เมื่อใดรูปหาย
- หน้าแรก แนะนำเครื่องมือ ขั้นตอน และตารางราคา · คำถามที่พบบ่อย · เงื่อนไขการใช้บริการ · นโยบายความเป็นส่วนตัว
- **เรียงสกินทำป้ายขายไอดี** (`/sort`) — 4 ขั้นตอน: **1) เลือกสกิน** (ค้นหา/กรอง เลือกทั้งหมดของฮีโร่ มุมมอง "จัดเรียง" ตามความหายาก/ฮีโร่/กำหนดเอง) → **2) พื้นหลัง** (อัปโหลดรูปของตัวเองแล้วครอปเป็น 1080×600 เหนือแถวสกิน หรือใช้ธีมสี 4 แบบ) → **3) ข้อมูลไอดี** (รหัสสินค้า ฮีโร่/สกิน อัตราชนะ จำนวนเล่น ราคา แบบเฉพาะตัวเลข ผ่อน แรงค์ VIP บัตรเปลี่ยนชื่อ คูปอง ไอเทมอื่น ช่องทางติดต่อ สกินต่อแถว) → **4) ชำระเงิน** (สรุปราคา ไม่มีลายน้ำ ดาวน์โหลด/แชร์) ทุกขั้นเห็นตัวอย่างป้ายสด ภาพสร้างในเบราว์เซอร์ทั้งหมด จำข้อมูลที่กรอกไว้ในเครื่อง และรูปพื้นหลังเก็บเฉพาะในเครื่อง ไม่อัปโหลดขึ้นเว็บ

**ระบบคอยน์ (จ่ายเมื่อดาวน์โหลด)**
- ใครก็เลือก จัดเรียง ตกแต่ง และดูตัวอย่างได้ฟรี ภาพตัวอย่างมีลายน้ำ "ตัวอย่าง" จนกว่าจะจ่าย
- ราคาคิดตามจำนวนสกินในภาพ: `จำนวนสกิน × ราคาต่อสกิน` (+ ค่าไม่มีลายน้ำ OSCAR ถ้าเลือก) แสดงราคาก่อนจ่ายทุกครั้ง · 1 บาท = 1 คอยน์ · คอยน์ไม่หมดอายุ
- เซิร์ฟเวอร์เป็นคนคำนวณราคาจาก id สกินที่มีอยู่จริง และหักคอยน์ด้วยคำสั่งเดียวแบบมีเงื่อนไข (ยอดติดลบไม่ได้แม้กดพร้อมกัน) ทุกการดาวน์โหลดถูกบันทึกในตาราง `Download`
- จ่ายครั้งเดียวต่อป้าย ดาวน์โหลด/แชร์ซ้ำป้ายเดิม (ข้อมูลไม่เปลี่ยน) ไม่เสียเพิ่ม
- สมัครด้วยอีเมล + รหัสผ่าน (`/register`) แอดมินตั้งคอยน์ฟรีตอนสมัครได้ (1 ครั้งต่ออุปกรณ์) · เปลี่ยนรหัสผ่านเองได้ที่ `/password` (ทั้งสมาชิกและแอดมิน)
- หน้า `/terms` (เงื่อนไขการใช้บริการ/คอยน์/การคืนเงิน — ดึงราคาจริงจากหน้าตั้งค่า) และ `/privacy` (นโยบายความเป็นส่วนตัวตาม PDPA) ลิงก์จาก footer หน้าสมัคร และหน้าเติมคอยน์ — ควรให้ผู้รู้กฎหมายตรวจถ้อยคำก่อนเปิดจริง
- หน้า `/account`: ยอดคอยน์ เลือกจำนวนเติม (20/50/100/300 หรือกำหนดเอง) QR พร้อมเพย์ใส่ยอดให้ อัปโหลดสลิป ประวัติเติม/ดาวน์โหลด
- **รายเดือน** (ค่าเริ่มต้น 199 คอยน์ / 30 วัน): ซื้อด้วยคอยน์ที่หน้า `/account` ระหว่างใช้งาน ดาวน์โหลดฟรีไม่จำกัด รวมแบบไม่มีลายน้ำ ต่ออายุล่วงหน้าได้ วันบวกต่อ (ตั้งราคา 0 = ปิดแพ็กเกจนี้) ถ้ารายเดือนหมดระหว่างเปิดหน้าอยู่ ระบบจะไม่หักคอยน์เงียบๆ แต่ให้รีเฟรชเพื่อดูราคาก่อน
- **แจ้งเตือนแอดมินฟรีทาง Telegram และ/หรือ Discord** เมื่อมีสลิปรอตรวจ เติมคอยน์อัตโนมัติ หรือมีคนสมัครรายเดือน (ส่งหลังตอบลูกค้าแล้ว ไม่ทำให้ช้า, อีเมลลูกค้าถูกปิดบางส่วน, ส่งไม่สำเร็จไม่กระทบการชำระเงิน)
- สลิปที่ SlipOK ตรวจผ่าน → เติมคอยน์ทันทีตามยอดในสลิป, สลิปซ้ำ/ยอดไม่ตรง → ปฏิเสธ, กรณีอื่น (ยังไม่ตั้งค่า SlipOK, ระบบล่ม, โควต้าหมด) → รอแอดมินอนุมัติ

**ฝั่งแอดมิน** (`/admin`, ต้องเข้าสู่ระบบ)
- แดชบอร์ดเว็บทำป้าย: รายได้เดือนนี้ ดาวน์โหลดและคอยน์ที่ใช้เดือนนี้ สมาชิก สลิปรอตรวจ คอยน์คงค้างของสมาชิก
- การชำระเงิน (`/admin/payments`): ดูสลิป (ลิงก์ชั่วคราวจาก bucket ส่วนตัว) แล้วกดอนุมัติ/ไม่อนุมัติ
- สมาชิก (`/admin/members`): ค้นหาอีเมล ดูยอดคอยน์ เพิ่ม/หักคอยน์เองได้
- ตั้งค่าร้าน: เลขพร้อมเพย์ ชื่อบัญชี ราคาต่อสกิน ค่าไม่มีลายน้ำ คอยน์ฟรีตอนสมัคร ยอดเติมขั้นต่ำ ราคาและจำนวนวันของรายเดือน
- **นำเข้าทั้งชุด** ที่ `/admin/skins`: วางรายชื่อบรรทัดละสกิน `ฮีโร่ | สกิน | ระดับ | ตำแหน่ง` (สองช่องท้ายไม่ใส่ก็ได้) ระบบสร้างฮีโร่ที่ยังไม่มีให้เอง ข้ามชื่อที่มีอยู่แล้ว ครั้งละไม่เกิน 600 บรรทัด
- **ใส่รูปสกินด้วยตัวครอป:** เลือกรูปหรือภาพแคปหน้าจอ (รองรับ HEIC จาก iPad) → ลากเลื่อน/ซูมด้วยแถบหรือบีบสองนิ้ว → ตัดเป็นสัดส่วน 4:5 ขนาด 480×600 JPEG อัตโนมัติ (ไฟล์เล็ก ช่องสกินทุกช่องรูปร่างเหมือนกัน) หน้าฮีโร่แต่ละตัวมีตัวเลข "ยังไม่มีรูป" และปุ่มแสดงเฉพาะสกินที่ยังไม่มีรูป
- คลังสกิน (`/admin/skins`): เพิ่ม/แก้ไข/ลบฮีโร่และสกิน ตั้งระดับ (SSS, SS, S+, S, A, Limited, ทั่วไป) อัปโหลดรูป หรือวางรายชื่อหลายสกินพร้อมกันแบบ `ชื่อสกิน | ระดับ` บรรทัดละรายการ (สกินที่ยังไม่มีรูปจะแสดงเป็นไทล์สีอัตโนมัติ)
- ตั้งค่าร้าน: แก้ลิงก์ติดต่อแอดมิน (Facebook/Line) ได้เองจากหน้าเว็บ ไม่ต้องแก้โค้ด

> ลิงก์เก่าของร้านขายไอดี (`/accounts`, `/policy`, `/admin/accounts`) จะเด้งไปหน้าทำป้าย/เงื่อนไขการใช้บริการ ตารางข้อมูลไอดีเดิม (GameAccount, AccountImage, Testimonial) ยังอยู่ในฐานข้อมูลแต่ไม่ได้ใช้แล้ว

## เทคโนโลยีที่ใช้

- [Next.js 16](https://nextjs.org/) (App Router, Server Actions, TypeScript)
- [TailwindCSS](https://tailwindcss.com/) สำหรับธีมเกมมิ่งโทนเข้ม
- [Prisma ORM](https://www.prisma.io/) + PostgreSQL (แนะนำ [Supabase](https://supabase.com/)) สำหรับฐานข้อมูล
- [Supabase Storage](https://supabase.com/storage) สำหรับเก็บรูปสกินและสลิปโอนเงิน
- [NextAuth.js](https://next-auth.js.org/) (Credentials provider, JWT session) สำหรับล็อกอินแอดมิน
- [Zod](https://zod.dev/) สำหรับ validate ข้อมูลทุกฟอร์ม

## เริ่มต้นใช้งาน (พัฒนาในเครื่อง)

### สิ่งที่ต้องมี

- Node.js 20.9 ขึ้นไป (แนะนำ 22)
- ฐานข้อมูล PostgreSQL สักตัว — ใช้โปรเจกต์ Supabase (ดูหัวข้อ Deploy ด้านล่าง) หรือรัน Postgres ในเครื่องผ่าน Docker ก็ได้:
  ```bash
  docker run --name rovshop-db -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:16
  ```

### ติดตั้ง

```bash
npm install
cp .env.example .env   # ใส่ DATABASE_URL/DIRECT_URL และค่าอื่นๆ ให้ครบ
```

สร้างตารางในฐานข้อมูลและใส่ข้อมูลตัวอย่าง:

```bash

npm run prisma:seed
```

รันเซิร์ฟเวอร์สำหรับพัฒนา:

```bash
npm run dev
```

เปิด [http://localhost:3000](http://localhost:3000)

## Deploy ขึ้น Render + Supabase

> เว็บนี้รันเป็นเซิร์ฟเวอร์ Node ธรรมดา (`next start`) บน Render ส่วนฐานข้อมูลและรูปอยู่ที่ Supabase
> **แผน Free ของ Render** ใช้ได้ แต่เว็บจะ "หลับ" ถ้าไม่มีคนเข้า 15 นาที (คนถัดไปต้องรอปลุกประมาณ 1 นาที) — แก้ด้วยการตั้งบอทยิงทุก 10 นาที (ดูข้อ 4) เมื่อมีรายได้แล้วแนะนำอัปเกรดเป็นแผนที่ไม่หลับ (Starter) ในหน้า Settings ของเว็บบน Render ได้ทันทีโดยไม่ต้องแก้โค้ด

### 1. ตั้งค่า Supabase (ฐานข้อมูล + ที่เก็บรูป)

1. ไปที่โปรเจกต์ Supabase → กดปุ่ม **Connect** (แถบบนสุด) → แท็บ **Direct** (หรือแท็บ **ORM** → Prisma) → เลือก **Session pooler** (พอร์ต **5432**) แล้วคัดลอกลิงก์ — ใช้**ลิงก์ Session pooler ตัวเดียวกัน**เป็นทั้ง `DATABASE_URL` และ `DIRECT_URL`
   - รูปแบบ: `postgresql://postgres.<รหัสโปรเจกต์>:<รหัสผ่าน>@aws-<n>-<ภูมิภาค>.pooler.supabase.com:5432/postgres`
   - แทน `[YOUR-PASSWORD]` ด้วยรหัสผ่านฐานข้อมูล (ลบวงเล็บ `[ ]` ด้วย) ถ้ารหัสมีอักขระพิเศษ เช่น `+` ต้องแปลงเป็น `%2B` — หรือกด **Reset database password** แล้วให้ระบบสุ่มรหัสที่มีแต่ตัวอักษร/ตัวเลข จะได้ไม่ต้องแปลง
   - ❌ **ไม่ใช้ Direct connection** (IPv6 — Render เชื่อมไม่ได้) และ**ยังไม่ใช้ Transaction pooler (6543)** เพราะ Supabase แจ้งว่าใช้ IPv6 เป็นค่าเริ่มต้น เว็บนี้รันเป็นเซิร์ฟเวอร์ตัวเดียว Session pooler เพียงพอ
2. ไปที่ **Project Settings → API Keys**: คัดลอก **Secret key** (ขึ้นต้น `sb_secret_` — ถ้าไม่มีให้ใช้ `service_role` ในแท็บ Legacy) ใช้เป็น `SUPABASE_SERVICE_ROLE_KEY` และคัดลอก **Project URL** (`https://<รหัสโปรเจกต์>.supabase.co`) ใช้เป็น `NEXT_PUBLIC_SUPABASE_URL` — Secret key เป็นความลับ ห้ามโพสต์/ส่งใคร (Publishable key `sb_publishable_` เว็บนี้ไม่ใช้)
3. ไปที่ **Storage** → สร้าง bucket ใหม่ชื่อ `product-images` → เปิด **Public bucket** (เพื่อให้รูปแสดงบนเว็บได้โดยตรง)
4. สร้างอีก bucket ชื่อ `payment-slips` → **ปิด** Public bucket (สลิปมีชื่อ/เลขบัญชีลูกค้า แอดมินดูผ่านลิงก์ชั่วคราวเท่านั้น)
5. (ไม่บังคับ) สมัคร [SlipOK](https://slipok.com) เพื่อตรวจสลิปอัตโนมัติ แล้วนำ Branch ID และ API Key มาใส่ `SLIPOK_BRANCH_ID` / `SLIPOK_API_KEY` — ในหน้าตั้งค่าของ SlipOK ควรตั้งบัญชีผู้รับให้ตรงกับพร้อมเพย์ของร้าน เพื่อให้ระบบปฏิเสธสลิปที่โอนเข้าบัญชีอื่น
6. (ไม่บังคับ) แจ้งเตือนแอดมิน:
   - **Telegram:** คุยกับ [@BotFather](https://t.me/BotFather) → `/newbot` → ได้ token, ส่งข้อความหาบอทของตัวเอง 1 ครั้ง แล้วเปิด `https://api.telegram.org/bot<TOKEN>/getUpdates` ดูเลข `chat.id` → ใส่ `TELEGRAM_BOT_TOKEN` และ `TELEGRAM_CHAT_ID`
   - **Discord:** ตั้งค่าช่อง → Integrations → Webhooks → New Webhook → Copy Webhook URL → ใส่ `DISCORD_WEBHOOK_URL`

> ภูมิภาคของ Supabase เลือกเอเชียตัวไหนก็ได้ (เช่น Tokyo/Singapore) ส่วน Render เลือก **Singapore** — อยู่ใกล้กัน ตอบสนองเร็วพอ

### 2. Deploy บน Render

1. ที่ [Render](https://dashboard.render.com) สมัคร/เข้าสู่ระบบด้วย GitHub → **New → Web Service** → เลือก repo `cyos8147/rovshop` (branch `main`)
2. ตั้งค่า:

   | ช่อง | ค่า |
   | --- | --- |
   | Language / Runtime | **Node** |
   | Region | **Singapore** (ใกล้ไทยที่สุด — ถ้ามีให้เลือก) |
   | Build Command | `npm ci --include=dev && npm run build && npm run admin:ensure` |
   | Start Command | `npm run start` |
   | Instance Type | **Free** (หรือ Starter ถ้าไม่อยากให้หลับ) |
   | Health Check Path (ใน Advanced) | `/api/health` |

   > `npm run build` จะรัน `prisma migrate deploy` (สร้าง/อัปเดตตารางในฐานข้อมูลให้เอง) แล้วค่อย build — ทุกครั้งที่ deploy
   > `npm run admin:ensure` สร้างบัญชีแอดมินจาก `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD` ถ้ายังไม่มี (มีแล้วจะไม่แตะ ไม่ทับรหัสที่เปลี่ยนภายหลัง และไม่ใส่ข้อมูลตัวอย่าง) — แผน Free ของ Render ไม่มี Shell ให้รันคำสั่งเอง จึงใช้วิธีนี้
   > `--include=dev` ต้องมี เพราะเครื่องมือ build (Prisma, Tailwind, TypeScript) อยู่ใน devDependencies

3. ใส่ **Environment Variables** ตามนี้ (เอาค่าจริงจาก Supabase ในข้อ 1) แล้วกด **Create Web Service**:

   | ชื่อตัวแปร | ค่า |
   | --- | --- |
   | `NODE_VERSION` | `22` |
   | `DATABASE_URL` | ลิงก์ **Session pooler** จากข้อ 1 **ต่อท้ายด้วย** `?connection_limit=5` (จำกัดจำนวนการเชื่อมต่อให้พอดีกับแผนฟรีของ Supabase) |
   | `DIRECT_URL` | ลิงก์ **Session pooler** ตัวเดียวกัน (ไม่ต้องต่อท้ายอะไร) ใช้สำหรับสร้าง/อัปเดตตาราง |
   | `NEXTAUTH_SECRET` | สุ่มค่าใหม่ด้วย `openssl rand -base64 32` |
   | `NEXTAUTH_URL` | ลิงก์เว็บจริง เช่น `https://ชื่อเว็บ.onrender.com` — **ข้ามได้ตอน deploy ครั้งแรก** (ถ้าไม่ใส่ ระบบใช้ลิงก์ที่ Render กำหนดให้เองจาก `RENDER_EXTERNAL_URL`) แต่**ต้องใส่เมื่อผูกโดเมนของตัวเอง** |
   | `SEED_ADMIN_EMAIL` | อีเมลแอดมินที่ต้องการ |
   | `SEED_ADMIN_PASSWORD` | รหัสผ่านแอดมิน อย่างน้อย 10 ตัว ห้ามใช้ `Admin1234!` (ระบบจะไม่ยอมสร้าง) |
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL จาก Supabase |
   | `SUPABASE_SERVICE_ROLE_KEY` | Secret key จาก Supabase (`sb_secret_…` หรือ `service_role`) |
   | `SUPABASE_STORAGE_BUCKET` | `product-images` |
   | `SUPABASE_SLIP_BUCKET` | `payment-slips` |
   | `SLIPOK_BRANCH_ID` | Branch ID จาก SlipOK (ไม่บังคับ) |
   | `SLIPOK_API_KEY` | API Key จาก SlipOK (ไม่บังคับ, เป็นความลับ) |
   | `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | แจ้งเตือนทาง Telegram (ไม่บังคับ, token เป็นความลับ) |
   | `DISCORD_WEBHOOK_URL` | แจ้งเตือนทาง Discord (ไม่บังคับ, เป็นความลับ) |

4. **กันเว็บหลับ (เฉพาะแผน Free):** สมัคร [cron-job.org](https://cron-job.org) (ฟรี) → Create cronjob → URL `https://ชื่อเว็บ.onrender.com/api/health` → ทุก 10 นาที
   - แผน Free ให้ชั่วโมงใช้งานฟรีรวมกันประมาณ 750 ชั่วโมง/เดือน **ต่อ workspace** — เปิดตลอดเดือนใช้ราว 720–744 ชั่วโมง พอดีสำหรับเว็บเดียว **อย่าสร้างบริการ Free ตัวที่สองใน workspace เดียวกัน** ไม่งั้นชั่วโมงหมดกลางเดือนแล้วเว็บถูกพักจนเดือนใหม่
   - `/api/health` แตะฐานข้อมูลด้วย จึงช่วยให้ Supabase แผนฟรีไม่ถูกพักเพราะไม่มีการใช้งานไปพร้อมกัน
   - Render อาจรีสตาร์ทบริการ Free ได้ทุกเมื่อ และไม่แนะนำแผน Free สำหรับใช้งานจริงระยะยาว — พอมีลูกค้าจ่ายเงินแล้ว อัปเกรดเป็น Starter (ประมาณ 7 ดอลลาร์/เดือน) แล้วเลิกใช้บอทได้

### 3. เข้าใช้งานครั้งแรก

บัญชีแอดมินถูกสร้างให้อัตโนมัติตอน deploy (จาก `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD`) — ดูข้อความ `ensure-admin: created admin ...` ใน Logs ของ deploy

เข้า `https://<โดเมนของคุณ>/login` ด้วยบัญชีแอดมิน แล้วไปที่ **ตั้งค่าร้าน** ใส่ลิงก์ Facebook และ**เลขพร้อมเพย์** (ถ้ายังไม่ใส่ ลูกค้าจะเติมคอยน์ไม่ได้) จากนั้นเพิ่มฮีโร่และสกินที่ **คลังสกิน**

> ถ้าอยากได้ข้อมูลตัวอย่าง (ไอดี/ฮีโร่/สกินตัวอย่าง) ให้รัน `npm run prisma:seed` จากเครื่องตัวเองโดยตั้ง `DATABASE_URL`/`DIRECT_URL` ชี้ไปที่ Supabase — ไม่จำเป็นสำหรับเว็บจริง

## คำสั่งที่ใช้บ่อย

| คำสั่ง | อธิบาย |

## หมายเหตุด้านความปลอดภัย

- รหัสผ่านแอดมินเข้ารหัสด้วย bcrypt ก่อนบันทึกเสมอ
- มี rate limiting เบื้องต้นป้องกันการยิงฟอร์มเข้าสู่ระบบถี่เกินไป (ใช้ได้ดีบน server เดียว หากภายหลังขยายเป็นหลาย instance ควรย้ายไป Redis)
- ไฟล์รูปภาพที่อัปโหลดถูกตรวจสอบชนิดไฟล์และขนาดก่อนเสมอ แล้วบันทึกด้วยชื่อไฟล์สุ่มใหม่ (ไม่ใช้ชื่อไฟล์จากผู้ใช้โดยตรง)
- สลิปโอนเงินเก็บใน bucket ส่วนตัว แอดมินดูผ่าน signed URL อายุ 1 ชั่วโมง, `transRef` ของสลิปเป็น unique ใช้ซ้ำไม่ได้, การอนุมัติซ้ำ (กดสองครั้ง) ไม่เติมคอยน์ซ้ำ
- **ข้อจำกัดที่ควรรู้:** การหักคอยน์ทำฝั่งเซิร์ฟเวอร์ แต่ตัวภาพสร้างในเบราว์เซอร์ คนที่ใช้ DevTools เป็นยังเลี่ยงลายน้ำ "ตัวอย่าง" ได้ — กันผู้ใช้ทั่วไปได้ ถ้าต้องการกันเด็ดขาดต้องย้ายการสร้างภาพไปฝั่งเซิร์ฟเวอร์ และคอยน์ฟรีตอนสมัคร "1 ครั้งต่ออุปกรณ์" ใช้คุกกี้ ล้างคุกกี้แล้วสมัครใหม่ได้ (ยังไม่มีการยืนยันอีเมล) — ถ้าเปิดแจกคอยน์ฟรีควรตั้งจำนวนน้อยๆ
- `SUPABASE_SERVICE_ROLE_KEY` ใช้เฉพาะฝั่งเซิร์ฟเวอร์เท่านั้น (ไม่มี prefix `NEXT_PUBLIC_`) จึงไม่ถูกส่งไปยังเบราว์เซอร์ของผู้ใช้
- เส้นทาง `/admin/*` ทั้งหมดถูกป้องกันทั้งที่ระดับ proxy (middleware) และระดับหน้า
