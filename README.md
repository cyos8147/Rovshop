# RoVShop

เว็บไซต์ขายไอดีเกม RoV (Arena of Valor) แบบครบวงจร สร้างด้วย Next.js (App Router) — มีหน้าร้านสำหรับลูกค้า ระบบตะกร้า/เช็คเอาต์ พร้อมอัปโหลดสลิปโอนเงิน และแผงควบคุมแอดมินสำหรับจัดการสต๊อกไอดีและคำสั่งซื้อ

> เว็บไซต์นี้เป็นตัวอย่างสำหรับสาธิตระบบ (demo) ระบบชำระเงินเป็นการจำลอง (แจ้งโอน + แนบสลิปให้แอดมินตรวจสอบ) ยังไม่ได้เชื่อมต่อเกตเวย์ชำระเงินจริง

## ฟีเจอร์หลัก

**ฝั่งลูกค้า**
- หน้าแรกพร้อมไอดีแนะนำและรีวิวลูกค้า
- หน้ารวมไอดีพร้อมค้นหา/กรอง (แรงค์ เซิร์ฟเวอร์ ประเภทล็อกอิน ช่วงราคา) และเรียงลำดับ
- หน้ารายละเอียดไอดี พร้อมแกลเลอรีรูปภาพและสเปกครบ
- ตะกร้าสินค้า (เก็บในเบราว์เซอร์) และเช็คเอาต์ เลือกวิธีชำระเงิน (โอนธนาคาร/พร้อมเพย์/TrueMoney)
- อัปโหลดสลิปโอนเงินต่อคำสั่งซื้อ ระบบจะแสดงข้อมูลบัญชี (ยูสเซอร์/รหัสผ่าน) ให้เฉพาะหลังแอดมินยืนยันการชำระเงินแล้วเท่านั้น
- ระบบสมาชิก (สมัคร/เข้าสู่ระบบด้วยอีเมล-รหัสผ่าน) และหน้าประวัติคำสั่งซื้อ

**ฝั่งแอดมิน** (`/admin`, ต้องเป็นบัญชีที่มี role เป็น ADMIN)
- แดชบอร์ดสรุปจำนวนไอดี สถานะ และยอดขาย
- จัดการไอดี: เพิ่ม/แก้ไข/ลบ อัปโหลดรูปหลายรูป ตั้งราคา/ส่วนลด/สถานะ และข้อมูลบัญชีสำหรับส่งมอบ
- จัดการคำสั่งซื้อ: ดูสลิป ยืนยันการชำระเงิน ทำเครื่องหมายส่งมอบไอดีแล้ว หรือยกเลิกคำสั่งซื้อ

## เทคโนโลยีที่ใช้

- [Next.js 16](https://nextjs.org/) (App Router, Server Actions, TypeScript)
- [TailwindCSS](https://tailwindcss.com/) สำหรับธีมเกมมิ่งโทนเข้ม
- [Prisma ORM](https://www.prisma.io/) + SQLite สำหรับฐานข้อมูล (เปลี่ยนเป็น PostgreSQL/MySQL ได้ง่ายเมื่อขึ้นโปรดักชัน)
- [NextAuth.js](https://next-auth.js.org/) (Credentials provider, JWT session)
- [Zustand](https://zustand-demo.pmnd.rs/) สำหรับตะกร้าสินค้าฝั่งไคลเอนต์
- [Zod](https://zod.dev/) สำหรับ validate ข้อมูลทุกฟอร์ม

## เริ่มต้นใช้งาน

### สิ่งที่ต้องมี

- Node.js 20.9 ขึ้นไป (แนะนำ 22)

### ติดตั้ง

```bash
npm install
cp .env.example .env   # ปรับค่าตามต้องการ โดยเฉพาะ NEXTAUTH_SECRET
```

สร้างฐานข้อมูลและข้อมูลตัวอย่าง:

```bash
npx prisma migrate deploy   # หรือ npm run prisma:migrate ในครั้งแรกที่ยังไม่มี migration
npm run prisma:seed
```

รันเซิร์ฟเวอร์สำหรับพัฒนา:

```bash
npm run dev
```

เปิด [http://localhost:3000](http://localhost:3000)

### บัญชีทดสอบ (จากข้อมูลตัวอย่าง)

| บทบาท | อีเมล | รหัสผ่าน |
| --- | --- | --- |
| แอดมิน | `admin@rovshop.dev` | `Admin1234!` |
| ลูกค้า | `customer1@example.com` | `Customer1234!` |
| ลูกค้า | `customer2@example.com` | `Customer1234!` |

อีเมล/รหัสผ่านของแอดมินตั้งค่าได้ผ่าน `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` ใน `.env` ก่อนรัน seed — ควรเปลี่ยนรหัสผ่านก่อนใช้งานจริง

## คำสั่งที่ใช้บ่อย

| คำสั่ง | อธิบาย |
| --- | --- |
| `npm run dev` | รันเซิร์ฟเวอร์สำหรับพัฒนา |
| `npm run build` | build โปรดักชัน |
| `npm run start` | รันเซิร์ฟเวอร์โปรดักชัน (ต้อง build ก่อน) |
| `npm run prisma:migrate` | สร้าง/อัปเดต migration ระหว่างพัฒนา |
| `npm run prisma:seed` | ใส่ข้อมูลตัวอย่าง (ไอดี, ผู้ใช้, รีวิว) |
| `npm run db:reset` | ล้างฐานข้อมูลและ seed ใหม่ทั้งหมด |

## โครงสร้างโปรเจกต์

```
prisma/
  schema.prisma        # โมเดลฐานข้อมูล (User, GameAccount, Order, ...)
  seed.ts               # ข้อมูลตัวอย่าง
src/
  app/                  # หน้าเว็บและ API routes (Next.js App Router)
    admin/              # แผงควบคุมแอดมิน
    accounts/            # หน้ารวม/รายละเอียดไอดี
    api/                 # NextAuth route + placeholder image generator
    ...
  components/           # React components ที่ใช้ร่วมกัน
  lib/
    actions/             # Server Actions (auth, accounts, orders)
    auth.ts              # ตั้งค่า NextAuth + helper ตรวจสอบสิทธิ์
    prisma.ts             # Prisma client singleton
    types.ts              # ค่าคงที่/union type แทน enum (SQLite ไม่รองรับ enum ใน Prisma)
  proxy.ts               # ป้องกันเส้นทาง /admin, /account, /checkout, /orders
```

## หมายเหตุด้านความปลอดภัย

- รหัสผ่านผู้ใช้เข้ารหัสด้วย bcrypt ก่อนบันทึกเสมอ
- ข้อมูลบัญชีเกม (ยูสเซอร์/รหัสผ่านไอดี) จะถูกส่งให้ลูกค้าเห็นก็ต่อเมื่อคำสั่งซื้อมีสถานะ "ชำระเงินแล้ว" เท่านั้น และต้องเป็นเจ้าของคำสั่งซื้อหรือแอดมิน
- มี rate limiting เบื้องต้นป้องกันการยิงฟอร์มเข้าสู่ระบบ/สมัครสมาชิกถี่เกินไป
- ไฟล์ที่อัปโหลด (สลิป/รูปไอดี) ถูกตรวจสอบชนิดไฟล์และขนาด แล้วบันทึกด้วยชื่อไฟล์สุ่มใหม่เสมอ (ไม่ใช้ชื่อไฟล์จากผู้ใช้โดยตรง)
- เส้นทาง `/admin`, `/account`, `/checkout`, `/orders/*` ถูกป้องกันทั้งที่ระดับ proxy (middleware) และระดับหน้า

ก่อนใช้งานจริงควรเพิ่มเติม: เชื่อมต่อเกตเวย์ชำระเงินจริง (เช่น Omise, 2C2P), ย้ายฐานข้อมูลไป PostgreSQL/MySQL, ย้ายไฟล์อัปโหลดไปเก็บบน object storage (เช่น S3/Cloudinary) แทนดิสก์ในเครื่อง และตั้งค่า `NEXTAUTH_SECRET` เป็นค่าสุ่มใหม่ที่ปลอดภัย
